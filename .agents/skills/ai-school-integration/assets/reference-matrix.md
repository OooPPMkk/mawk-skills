# 参考对照表

本批参考过 `bt/*` 前端实现或产品原型时，交付必须附这张表（用户据此核对有没有照搬）。逐项列出，不要合并成一段话。

```markdown
## 参考对照表（B<n>）

| 参考项 | 参考做法 | 本仓实现 | 差异与理由 |
| --- | --- | --- | --- |
| <页面 / 交互 / 边界项> | <参考里怎么做的> | <本仓怎么做> | <不同点：命名 / 组件 / 样式 Token / 复用既有组件 / 文案规范 …> |

### 只取了意图、未取实现的部分
- <项>：参考用 <做法>，本仓改为 <做法>（理由：<规范 / 既有页面一致性 / 复用>）

### 参考里没有做、本仓补上的部分
- <项>：<补齐的内容与依据（行业规范 / 本仓规范 / 用户确认）>

### 未采纳的参考项
- <项>：<为什么不用>
```

写表时的要求：

- 「差异与理由」必须写实：不能整列都是「命名不同」这类空话，差异要落到本仓规范或既有页面。
- 若某项确实与参考做法相同，直接写「与参考一致」并说明是独立推导出的同一结论（如都被 Token 规范约束），不要含糊。
- 表格单元格内不出现裸 `|`（用 `/` 或转义）。
- 结论同步一行进 history 批次明细的「实现」段：`参考 bt/<分支> 实现独立完成，差异见对照表`。
