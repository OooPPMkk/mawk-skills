# 文档条目模板

## plan §2 待开始批次

```markdown
#### B<n> <批次名>（<依赖：v3 `XXX-n` / 1.0.x 端点>）

- 范围：<改哪个页面 / 哪个链路，具体到区块或函数名>
- 口径：<关键决策口径；展示形态、默认值、兜底策略>
- 依赖：<后端交付物 或 无>
```

挂起批次额外写清卡点：`依赖：v3 `WS-1` / `WS-2`（breaking）`。

## history §1 批次明细

```markdown
### B<n> <批次名>（<SHA>）

- 范围：<一段话说清改了哪些链路与文件范围（不逐文件罗列）>
- 口径：<结论式口径，含兜底与边界；超出本批的语义变化单独点名>
- 实现：<关键手段：新增的 composable / props / 服务层映射方式等，3-6 条>
- 验收：<测试身份 + 环境>；<端点与关键字段实测值>；<页面可见结果>；四件套通过。
- 验证边界：<真实数据不具备时的构造方式 / 未能覆盖的取值>
- 参考：<bt/分支 / 原型> 仅取意图，独立实现与差异见参考对照表（未参考则可省略此行）
- 依赖：<后端交付物> 或 无。
- 关联（可选）：<harness issue 编号闭环 / 重写口径>
```

## history §2 决策记录

```markdown
### D<n> <决策名>（<日期>）

- <结论 1>：<这么定的理由，以及影响到的批次或页面>
- <结论 2>：<…>
- 不跟：<明确不采纳的路由 / 方案 + 理由>
```

新增决策**只记 history**，plan §3 保持一行指针。

## issues-v3 缺陷条目

````markdown
## [<PREFIX>-<n>] <一句话说清问题>

`VERIFIED_IN_SOURCE` <源码出处：类 / 方法 + 实际行为>

`EVIDENCE` <日期>，测试身份（<账号> / <orgId>），api_base 实测：

```
<请求>
  -> <响应关键片段>
```

`EXPECTED` <期望形态；可给二选一或三选一并标注推荐>

`ACCEPTANCE` <验收判据：出现什么即视为解决>

`FRONTEND_INTERIM` <前端当前按什么口径实现；后端改动后要同步什么>
````

登记需求用 `REGISTERED_REQUIREMENT` 段（模板参考 v2 `COURSE-1`），不计入缺陷集与 `open_issue_count`。
